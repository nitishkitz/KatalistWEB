Connect a GitHub repository

See pull requests, pushes, and checks for one repository next to this List’s work, and turn a change into a Thing when you choose. Katalist only reads from GitHub. It never writes to it.

Everyone in this List will be able to read this repository’s activity, checks, and available diffs — including View Only members. Connecting is your decision as Owner. You will confirm this before anything is connected.

WHEN THE FEATURE IS OFF FOR THIS LIST
The Code Activity tab is not shown
No request is made and nothing appears. Things, Chat, and Members are unaffected.

Spec · Frame 01

  1. New tab Code Activity sits between Chat and Members & Permissions. Dashed outline marks the only change to existing chrome.
  2. Top navigation is the existing bar: Court, Lists, Buckets, Team, Nudges, Me, plus Catch Up, Work/Home toggle, bell, avatar. Height 56px, background #f5f8fe.
  3. Owner card: padding 32px, radius 12px, border #eaeffa. Heading 20px/600, body 14px, tag 12px. Max text width 560px.
  4. Sharing notice is visible before connecting and names View Only members explicitly. It is separate from AI consent (frame 07).
  5. Primary action Connect GitHub: 42px high, radius 9px, violet #975ee2, 2px focus ring offset 2px.
  6. Non-owners get no button, only an explanation. No GitHub request is made on tab open.
  7. Sample data only; nothing connects. Copy is draft and needs product review.

Spec · Frame 03

  1. Desktop split: activity list 35% (min 360px) and inspector 65% (min 560px) at 1440 and 1024+ widths.

Spec · Frame 06

  1. Five distinct check states: passed, failing, pending, none, unavailable, plus a labelled stale variant when the checks belong to an older revision. Stale checks are never shown as current success.
  2. Colour is always paired with an icon and text. Contrast of the proposed status colours is to be measured in T34.
  3. Rows 64px; name 13.5px/600; detail 12px. Each row links to the check on GitHub.

  5. Unavailable is a local state. It never turns the whole inspector or the feed into an error.
  6. Partial lists (more than the provisional 200-check limit) are labelled, not silently cut off.
  7. Retry affects this section only.

Spec · Frame 08

  1. Generation is cancellable at any time. Cancel returns to the note and evidence, with the user’s text preserved.
  2. Progress uses a short opacity/position transition of 160–220ms and a skeleton. No looping mascot animation in the reading surface. Reduced-motion removes the spinner’s motion.
  3. Status text sits in a polite live region: started, finished, failed, cancelled.
  4. Failures are local to the draft panel. Every failure keeps evidence visible and offers a manual path: "Create a Thing yourself" opens the existing creation flow.
  5. Retry preserves the user’s edits. A retry is a new request subject to the same consent check.
  6. No failure here may affect the feed, the other inspector tabs, or Things, Chat, and Members.

  2. A retry after a lost response returns the original Thing (state D); it never creates a second one. If the original was later removed, say so plainly.
  3. A successful retry is not blocked by later changes to the source, the connection, or consent. Only a new creation is subject to those checks.
  4. Source-changed (E) asks for an explicit second confirmation; it does not silently proceed.
  5. Not-allowed (F) preserves the user’s edits and offers the normal manual creation path.
  6. Success copy states the real outcome: Waiting for Catch, plus the in-app notification only when the assignee is another person. No push promise.
  7. Result updates are announced politely. Focus moves to the result heading, and returns to the Create control if the user goes back.
  8. A preview draft is labelled "Preview" and never links to a Thing.
